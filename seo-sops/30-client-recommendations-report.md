# SOP: Creating Client SEO Recommendations Report

## 1. Document Control
- **ID**: dn-seo-sop-30
- **Version**: 2.0
- **Owner Role**: Senior SEO Specialist
- **Trigger**: The SEO audit sheet is complete.
- **Inputs**: Completed SEO Audit Sheet, website URL, screenshot tool.
- **Outputs**: Actionable recommendations document with screenshots shared with the client.

---

## 2. Purpose & Objectives
This Standard Operating Procedure explains how to translate technical SEO audit findings into a clear report for the client. We explain the business impact of each issue and provide clear, actionable steps for developers. This ensures that client recommendations are easy to understand.

---

## 3. Required Tools
- Google Drive and Google Docs
- Completed client SEO Audit Sheet
- Screenshot tool (like Lightshot or clean browser screen capture tools)

---

## 4. Step-by-Step Instructions
1. **Open Audit Sheet**
   - Action: Open the completed client SEO Audit Sheet in Google Drive.
   - Expected Result: The spreadsheet loads and displays the audit tabs.
2. **Filter Critical Issues**
   - Action: Go to the technical audit tab and filter for issues marked as High or Medium priority.
   - Expected Result: You see a filtered list of key website errors.
3. **Create Recommendations Document**
   - Action: Create a new Google Document in the client folder and name it exactly: `[Client Brand Name] SEO Recommendations`.
   - Expected Result: A blank Google Document is created in the correct folder.
4. **Define the Opportunity**
   - Action: Write a short heading for each issue explaining what is currently broken on the website.
   - Expected Result: The issue headings are clear and descriptive.
5. **Explain Business Impact**
   - Action: Write a simple sentence explaining how fixing the issue will help the client business get more visibility or calls.
   - Expected Result: The business value is clear to the client.
6. **Write Actionable Recommendations**
   - Action: Write a direct instruction explaining how the developer must fix the issue.
   - Expected Result: The recommendation is actionable.
7. **Take Screenshots**
   - Action: Open the client website, locate the page containing the issue, and capture a screenshot of the error.
   - Expected Result: You have a screenshot showing the specific website error.
8. **Insert Screenshots**
   - Action: Paste the captured screenshot directly below the recommendation text in the document.
   - Expected Result: The screenshot is visible in the document.
9. **Remove Technical Jargon**
   - Action: Review the entire text to replace complex technical terms with simple plain English words.
   - Expected Result: The document is written at a fifth-grade reading level.
10. **Send for Internal Review**
    - Action: Share the Google Document link with Sagar to get approval before sending it to the client.
    - Expected Result: Sagar receives the link for review.

---

## 5. Quality Control & Measurable Checks
- [ ] Recommendations document created and properly named.
- [ ] Only High and Medium priority issues included.
- [ ] Business impact explained in simple terms for each recommendation.
- [ ] Actionable steps provided for the developer.
- [ ] Screenshots attached for each logged error.
- [ ] Technical jargon replaced with plain language.
- [ ] Shared with Sagar for internal approval.

---

## 6. Common Problems & Troubleshooting
| Problem | Likely Cause | Solution |
| :--- | :--- | :--- |
| The client does not understand the technical recommendations | Complex developer terms were used in the text | Rephrase the steps to focus on the business outcome. Use visual diagrams or simple analogies. |
| The developer cannot reproduce the error | No URL or screenshot was provided | Add the exact page URL and a clear screenshot highlighting the error in the document. |
